# ContextGuard — 1.0.0 benchmark

> Generated by `make benchmark` (`python -m contextguard_eval_harness.benchmark`). Do not edit by hand.

Library-only, zero-infra. Each scenario is run twice through `ContextGuard.guard()` — once with **no policy** (a naive RAG pass-through) and once with the shipped default policy (`data/policies/example.yaml`). A scenario *leaks* when its sensitive marker survives into the context the model would receive. Grading is a deterministic string check — no LLM-as-judge.

## What each scenario proves

### Cross-tenant leak

A sales user at `acme` runs a query whose top-k pulls in a semantically similar chunk that actually belongs to tenant `contoso`. A naive retriever serves it; the firewall must enforce tenant isolation.

### Confidential-chunk leak

A sales user retrieves an `acme` chunk classified `confidential` (an unannounced acquisition memo) that the sales role must never see. A naive retriever ranks it highly; the firewall must block it on classification.

### PII redaction

A legitimate, in-tenant chunk answers the question but carries personal data (email, phone) that the model does not need. Data minimization at the prompt boundary: the chunk stays, the PII is masked.

### Prompt injection in a retrieved document

An indirect prompt-injection payload is smuggled inside an otherwise ordinary in-tenant document. A naive RAG concatenates it into the prompt; the firewall scores the injection risk and drops the chunk.
